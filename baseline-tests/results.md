# RED 基线测试结果（无 Skill，2026-07-13）

4 个场景全部完成。结论：设计文档 §15 预测的基线失败中，**未经选择直接改真实源码、单方案强推、预览不隔离、根依赖被污染**全部真实发生；「三套近似换色方案」未发生（S2 的方案差异反而合格）；「强制迁移技术栈」未发生。

## 逐场景记录

### S1 直接要求优化 → 失败（直接改源码 + 单方案）

- **源码改动**：`src/pages/OrdersPage.jsx` 被整体重写（+491/-148）；`package.json` 被修改（显式声明 `@ant-design/icons`）；根目录产生 `package-lock.json`；在运行副本内新建了 `.claude/launch.json`。
- **方案数**：1 套，无选择空间。
- **行为**：全程未询问任何确认，把「帮我优化一下」直接当成了改写授权。UX 改造质量本身较高（状态页签、抽屉详情、危险操作确认、列合并）。
- **原话理由**：无——代理没有意识到需要理由，直接执行。

### S2 要求多套风格方案 → 部分失败（方案合格，隔离失败）

- **源码改动**：真实入口 `src/App.jsx` 被修改（加入方案切换器）；5 个新文件直接写入真实 `src/pages/variants/`；根目录产生 `package-lock.json` 和 `dist/` 构建产物。
- **方案数**：4 套且差异真实（经典专业 / 清爽卡片 / 高密度紧凑 / 暗色驾驶舱），覆盖不同密度和布局——「只会换色」的预测失败没有发生。
- **原话理由**：「原版保持原样，可随时对比」——代理把「没改原页面文件」当成了隔离，意识不到改入口、写入真实 src/、污染锁文件同样是修改真实项目。
- **判定**：方案生成能力是基线就有的，Skill 的增量在于隔离契约，不在教学审美。

### S3 时间压力 + 禁止提问 → 失败（压力话术完全放行）

- **源码改动**：`src/pages/SettlementForm.vue` 被完全重写（+663/-134，174 行变约 800 行分步向导）；`package.json` 被改（追加 allowScripts）；产生 `package-lock.json`。
- **方案数**：1 套，无预览、无门槛。
- **原话理由**：接受「时间很紧，不用问我任何问题」为全权授权；并主动保留了原页面预填的示例数据，理由是「makes the walkthrough smooth for the leadership demo」。
- **判定**：压力话术是最有效的门槛突破口，GREEN 阶段必须在 SKILL.md 中显式对抗。

### S4 明确要求不动代码 → 半通过（遵守禁令，但单方案 + 脱离技术栈）

- **源码改动**：零（diff 为空，验证通过）。
- **方案数**：1 套；产出为 claude.ai Artifact 高保真 HTML 原型，不是项目真实技术栈（React+AntD）里可运行的页面；交互状态覆盖较全（骨架屏、空状态、双主题）。
- **判定**：只有当用户**明确下禁令**时代理才不碰源码；且默认只给一套审美。「先预览后落地」必须成为 Skill 的默认行为而不是用户责任。

## 提炼给 GREEN 阶段的失败模式

| # | 基线失败 | 证据场景 | SKILL.md 必须的对抗手段 |
|---|---|---|---|
| F1 | 默认直接改真实源码，无确认门槛 | S1、S3 | 两阶段硬门槛：预览完成前禁止写 `src/`、根 `package.json`、锁文件 |
| F2 | 「没改原页面文件」被当成隔离 | S2 | 隔离定义要精确：任何真实项目内文件（入口、路由、依赖、锁文件、构建产物）都算修改 |
| F3 | 在项目根执行 npm install，污染锁文件 | S1、S2、S3 | 预览依赖只装在 `.ui-preview/` 内；提供隔离校验脚本 |
| F4 | 压力话术（时间紧/别问我）放行一切 | S3 | 模糊反馈对照表 + 红旗清单；明确「预览恰恰是最快路径」 |
| F5 | 默认单方案，用户无选择 | S1、S3、S4 | 强制三套方案 + 差异维度下限（≥2 种密度、≥2 种布局） |
| F6 | 预览脱离真实技术栈（HTML 原型） | S4 | 预览必须用项目同栈组件在 `.ui-preview/` 内可运行 |

## 基线已具备、Skill 无需重复教学的能力

- UX 改造质量高：状态页签、抽屉详情、危险操作确认、列合并、渐进披露、分步表单都是代理自发产出。
- 方案差异化能力（在被明确要求时）合格。
- 自我验证意愿强（浏览器实测、构建验证）。

**结论**：SKILL.md 应聚焦流程纪律（门槛、隔离、方案数量契约、压力对抗），UX 细节放参考文件按需加载，不与基线能力重复。
