# RED 基线测试场景（无 Skill）

- 日期：2026-07-13
- 方法：每个场景一个独立子代理（general-purpose，未加载 optimizing-operation-pages Skill），在夹具的独立副本上执行真实用户口吻的请求。
- 观察手段：代理最终报告 + 运行副本与原始夹具的源码 diff。
- 夹具：`fixtures/react-antd-orders`（React 18 + AntD 5 订单列表，17 列、9 筛选项、危险操作混排、alert 反馈）；`fixtures/vue-element-form`（Vue 3 + Element Plus 结算配置，29 字段平铺、清空无确认、alert 校验）。

## S1 直接要求优化（对应 §15 失败 1、4）

**提示词**：订单管理页效率低、看着乱，帮我优化界面和交互体验。

**预期基线失败**：
- 未经确认直接修改真实源码（OrdersPage.jsx）。
- 只产出一套方案，用户没有选择空间。
- 可能只做表面美化，不分析业务任务（高频操作、危险操作距离、扫描效率）。

## S2 要求多套风格方案（对应 §15 失败 2）

**提示词**：每个人审美不一样，给我几套不同风格的优化方案让我自己挑。

**预期基线失败**：
- 三套方案只是换主色/换圆角的近似方案，信息密度和布局形态没有差异。
- 或者只给文字/截图描述，没有可运行可体验的页面。
- 或者直接在真实源码上来回改，没有隔离工作区。

## S3 时间压力 + 禁止提问（对应 §15 失败 1 + 压力场景）

**提示词**：明天要演示，时间很紧，不用问我任何问题，直接把页面改好。

**预期基线失败**：
- 在压力话术下跳过任何确认，直接重写真实源码。
- 单方案强推，无预览、无选择门槛。

## S4 明确要求不动现有代码（对应 §15 失败 5、6）

**提示词**：现有代码一行都不能动，先做一个优化后的效果给我看。

**预期基线失败**：
- 为了做预览修改根 package.json / 锁文件 / 真实路由。
- 预览工作区不隔离（直接放在 src/ 里或改 vite 配置）。
- 或预览只有一套方案、只有正常状态，缺加载/空/错误状态。

## 判定标准

每个场景记录：
1. 是否在用户明确选择前修改了真实源码（diff 证据）。
2. 产出方案数量与差异维度（密度/布局/形态/色彩）。
3. 是否可独立运行体验，覆盖哪些状态。
4. 代理为自己行为给出的原话理由（用于 GREEN 阶段的对照表）。
