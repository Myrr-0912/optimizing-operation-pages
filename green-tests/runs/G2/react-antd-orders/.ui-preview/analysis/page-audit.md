# 订单管理页审计（src/pages/OrdersPage.jsx）

## 1. 主任务

运营人员按条件（订单号/客户/状态/时间等）**找到目标订单，查看关键信息并执行处理动作**（催发货、关闭、退款跟进、导出）。

## 2. 操作分级

| 操作 | 频率 | 危险性 | 现状问题 |
|---|---|---|---|
| 查询/筛选 | 高 | - | 9 个筛选控件平铺两行无折叠；"查询"按钮实际只重新拉数（过滤是即时的），语义混乱；无"重置" |
| 查看详情 | 高 | - | `window.alert(JSON.stringify(row))`，不可复制、不可读 |
| 催发货 | 高 | - | 行内文字按钮，可接受；但无任何状态前置校验 |
| 复制 | 中 | - | 行内按钮 |
| 导出全部 | 低 | - | `window.alert` 反馈 |
| 同步 ERP | 低 | - | 放在与查询同级的位置，反馈为"已刷新"文案错位 |
| 批量关闭 | 低 | **危险（不可逆）** | 无选中时也可点击且直接"完成"；无确认；`window.alert` 反馈 |
| 删除 | 低 | **危险（不可逆）** | `window.confirm('删除?')` 两字确认，与普通操作紧邻 |
| 拉黑 | 低 | **危险（影响客户）** | 无确认直接生效，与普通操作紧邻 |

## 3. 任务链（现状）

查询→筛选（2 行 9 控件里找目标）→ 横向滚动 2400px 找字段 → 行尾 5 个平铺按钮里找操作 → alert/confirm 弹窗。
找一笔订单并催发货 ≈ 4-6 次点击 + 至少一次横向滚动。

## 4. 信息分级（17 列 → 三档）

- **决策必需**：订单号、客户（姓名+手机）、金额、状态、创建时间、风险等级（风控场景）。
- **辅助**：渠道、支付方式、SKU 数、优惠、运费、备注、更新时间。
- **技术元数据（默认收进详情）**：ID（UUID，现状还是 300px 首列）、外部交易号、同步标记。

## 5. 状态盘点

| 状态 | 现状 |
|---|---|
| 正常 | 有 |
| 加载 | 仅表格默认 spinner |
| 空 | AntD 默认空图，无"清空筛选"引导 |
| 错误 | **缺失**（fetch 无 catch） |
| 成功 | window.alert / 语义不符的 message.info |

## 6. 违反 ux-rules 的证据清单

1. 元数据优先于主要信息：UUID 是第一列且宽 300px；同步标记、外部交易号占默认列。
2. 行内操作 5 个未收敛（规则：>3 收进"更多"）；删除/拉黑与普通操作相邻。
3. 危险操作确认不说明后果（"删除?"）；拉黑、批量关闭无确认。
4. 使用 window.alert / window.confirm（规则明令禁止）。
5. 批量操作在无选中时可用且假装成功。
6. 筛选 9 项全部常驻，无"更多筛选"折叠，无已选条件标签、无重置。
7. 金额未右对齐、无千分位；状态无颜色标签；时间戳原样拼接。
8. 横向滚动 2400px，仅操作列固定，订单号等关键列不固定。
9. 无错误态、无重试；导出等长任务无进度/去向链接。
