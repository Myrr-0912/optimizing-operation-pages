# 订单管理页审计（src/pages/OrdersPage.jsx）

## 1. 主任务

运营同事在大量订单中**快速定位目标订单（按单号/客户/状态/时间），查看关键信息并执行处理动作**（催发货、关闭、导出、处理风险单）。

## 2. 操作分级

| 操作 | 频率 | 危险性 | 现状问题 |
|---|---|---|---|
| 查询/筛选 | 高频 | - | 9 个筛选控件平铺两行，无"已选条件"展示，前端过滤但仍保留"查询"按钮语义混乱 |
| 查看详情 | 高频 | - | `window.alert(JSON.stringify(row))` 展示原始 JSON，不可用 |
| 催发货 | 高频 | - | 对任何状态订单都可点（待支付/已关闭也能催） |
| 导出 | 中频 | - | `window.alert` 反馈 |
| 复制 | 中频 | - | 只弹"已复制"，实际未复制任何内容 |
| 批量关闭 | 低频 | **危险** | 无确认、无选中数校验（0 选中也执行）、`window.alert` 反馈 |
| 删除 | 低频 | **危险** | `window.confirm('删除?')` 两字确认，与普通操作相邻，无后果说明 |
| 拉黑 | 低频 | **危险** | 一点即生效，无确认 |
| 同步ERP | 低频 | - | 假反馈"已刷新"，实际未刷新数据 |

## 3. 任务链现状

查询→筛选（2 行 9 控件里找）→ 横向滚动 2400px 找字段 → 操作列 5 个平铺链接里选 → alert/confirm 弹窗。
找一个订单并催发货：滚动 + 视觉扫描成本极高；高风险单无任何视觉突出。

## 4. 信息分级（现状 18 列 → 决策必需仅 8-9 个）

- **决策必需**：订单号、客户（姓名+手机号）、金额、状态、风险等级、创建时间、操作。
- **辅助**：外部交易号、渠道、支付方式、SKU数、优惠、运费、备注、更新时间。
- **技术元数据**（默认收进详情）：ID（UUID，宽 300px 占首列）、同步标记。

## 5. 状态盘点

| 状态 | 现状 |
|---|---|
| 正常 | 有 |
| 加载 | 仅 Table 内置 spin |
| 空 | AntD 默认空图，无"清空筛选"引导 |
| 错误 | **缺失**（mock 永不失败，真实接口失败无兜底） |
| 成功 | window.alert / message.info，混用且部分为假反馈 |

## 6. 问题清单（对照 ux-rules.md）

1. 【信息架构】UUID 首列 300px + 同步标记等元数据常驻，决策字段被挤出首屏；横向滚动 2400px。
2. 【信息架构】筛选 9 项全常驻无折叠；已生效条件不可见、不可单独移除。
3. 【操作效率】行内 5 个操作平铺，超过 3 个未收进"更多"。
4. 【操作效率】危险操作（删除/拉黑/批量关闭）与普通操作相邻，无距离无层级。
5. 【操作效率】批量关闭在 0 选中时也可执行且无确认。
6. 【错误预防】window.alert / window.confirm 违规使用（4 处）；确认文案"删除?"无后果说明。
7. 【错误预防】详情用 alert 展示 JSON；复制为假操作；同步ERP 假反馈。
8. 【数据页面】金额左对齐、无千分位、无货币符号；状态纯文字无色彩编码；风险等级无视觉突出。
9. 【数据页面】时间列手工 `replace('T',' ')` 截断，两列时间常驻占 340px。
10. 【可访问性】操作依赖 alert（阻塞、不可主题化）；状态仅靠文字/无颜色对比设计。
