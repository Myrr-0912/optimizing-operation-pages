# 订单管理页审计（src/pages/OrdersPage.jsx）

## 主任务

运营人员按单号 / 客户 / 状态等条件快速定位目标订单，并执行处理动作（查看详情、催发货、关闭、删除、拉黑），偶发批量处理与导出。

## 操作分级

| 操作 | 频率 | 危险性 | 现状问题 |
|---|---|---|---|
| 查询/筛选 | 高频 | - | 9 个筛选项两行平铺，无重置；"查询"按钮实际是重新加载全部数据，与前端即时筛选语义冲突 |
| 查看详情 | 高频 | - | `window.alert(JSON.stringify(row))`，不可读（行 92） |
| 催发货 | 高频 | - | 仅 message.info，无对象反馈 |
| 复制 | 中频 | - | 仅提示"已复制"，未真正写剪贴板 |
| 导出全部 | 低频 | - | `window.alert` 阻塞提示（行 64） |
| 同步 ERP | 低频 | - | 反馈文案是"已刷新"，与动作不符 |
| 批量关闭 | 低频 | 危险 | 无选中校验（空选中也提示"完成"）、无确认、`window.alert` 反馈（行 57-61） |
| 删除 | 低频 | 危险 | `window.confirm('删除?')` 两字确认，无后果说明（行 51）；与普通操作相邻 |
| 拉黑 | 低频 | 危险 | 无任何确认，直接提示"已加入黑名单"（行 104） |

## 信息分级

- 决策必需：订单号、客户、金额、状态、风险等级、创建时间。
- 辅助：外部交易号、渠道、支付方式、SKU 数、优惠、运费、备注、更新时间。
- 技术元数据（应默认收进详情）：ID（UUID，现占首列 300px）、同步标记（0/1 裸值）。

## 现状问题清单（对照 ux-rules.md）

1. 阻塞式原生弹窗：alert/confirm 用于详情、删除、批量关闭、导出（违反"禁止 window.alert / confirm"）。
2. 危险操作无隔离：删除、拉黑与高频操作并排，确认缺失或无后果说明。
3. 批量关闭在无选中时仍可点击并报"完成"，误导操作者。
4. 17 列全平铺、`scroll x=2400`，UUID 首列 300px，横向滚动成本极高；行内操作 5 个未收敛。
5. 金额左对齐、无千分位、无货币符号；状态、风险等级为纯文本，不可扫描。
6. 无空态（区分"无数据"与"筛选过窄"）、无错误态与重试、加载仅默认 spin。
7. 手机号 11 位明文展示，存在隐私暴露面。
8. 无已选筛选条件回显，无法单独移除某个条件。
9. 无任何汇总信息（总量/待处理/异常）辅助运营判断。

## 状态盘点

- 正常：有。加载：默认 spin。空：AntD 默认空图，无引导。错误：完全缺失（mock 永不失败也无 catch）。成功：alert / message.info 混用。
